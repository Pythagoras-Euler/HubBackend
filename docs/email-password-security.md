# 邮件链接与密码校验

验证邮件统一通过 `email_links.confirmation_link` 替换配置 `frontend_urls.email_confirm` 中的 `{domain}` 和 `{secret}`。注册验证、重发验证、邮箱更换、密码重置均使用该函数；自定义前端域名和路径保持有效，secret 作为查询参数进行 URL 编码。

注册、个人设置修改密码及邮件重置使用同一新密码策略：8–30 个 Unicode 字符，UTF-8 最多 72 字节，包含 ASCII 大写、小写、数字 0–9 和 `!@#$%^&*` 中至少一个符号，拒绝空白与 Unicode C 类字符（控制、格式、代理等）。不自动裁剪、去空格或规范化密码。校验失败不写入密码，也不消耗仍有效的重置令牌。

现有密码登录不套用新强度规则；bcrypt 哈希及其 Base64 存储方式保持不变。超过 bcrypt 的 72 字节输入按登录失败处理，不截断，也不再抛出服务器异常。

设置与重置页面持续显示中英文要求。当前登录页面按邮箱记录连续的 401 密码认证失败，第三次起提示检查邮箱、大小写和输入法或重置密码，并说明新密码规则不改变旧密码。验证码失败、429 限流和网络/服务器错误不增加计数；登录成功清零。此计数仅用于当前页面的帮助提示，刷新后重置，不是账户锁定机制；既有后端限流继续生效。

验证包括纯函数边界测试、三个实际密码写入入口的拒绝测试，以及使用本地模拟响应的浏览器交互测试。测试不向真实用户发送邮件，也不尝试真实账号密码。
